\section*{Resumen}
\addcontentsline{toc}{section}{Resumen}
\justifying

Este informe presenta el desarrollo de \textit{SmartRide Planner}, una simulación urbana de planeación de movimiento multi-agente implementada sobre una grilla discreta de $20 \times 20$. El sistema modela un servicio de transporte mediante taxis autónomos que deben recoger usuarios distribuidos en el entorno, evitando obstáculos representados como edificios y respetando restricciones de colisión entre agentes.

La solución fue desarrollada en Python siguiendo una arquitectura modular compuesta por una interfaz gráfica, un motor de simulación, un módulo de algoritmos de búsqueda de rutas, un módulo de asignación de tareas, un gestor de colisiones y una suite de pruebas. En la versión final se implementaron cuatro algoritmos de ruta: A*, Dijkstra, BFS y Greedy Best-First Search. Además, se incorporaron dos criterios de asignación: taxi más cercano y usuario prioritario.

El problema se formuló como una búsqueda sobre grafos, donde cada celda transitable del entorno corresponde a un nodo y cada movimiento válido hacia una celda adyacente representa una arista. A partir de esta representación, se evalúan rutas entre taxis y usuarios considerando distancia, prioridad de usuarios y restricciones de ocupación.

La validación del sistema se realizó mediante una suite de pruebas que verifica el cálculo de rutas, la asignación multi-agente, la detección de colisiones, la prevención de cruces conflictivos, la generación aleatoria de escenarios, la replaneación dinámica y la configuración variable de taxis y usuarios. El resultado final de la suite fue de 28 pruebas aprobadas y 0 errores.

\textbf{Palabras clave:} robótica multi-agente, planeación de movimiento, grafos, A*, Dijkstra, BFS, Greedy Best-First, optimización, simulación computacional, asignación de tareas.

\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}
\justifying

This report presents the development of \textit{SmartRide Planner}, an urban multi-agent motion planning simulation implemented on a discrete $20 \times 20$ grid. The system models a transportation service in which autonomous taxi agents must pick up users distributed across the environment while avoiding obstacles and respecting collision constraints.

The solution was developed in Python using a modular architecture composed of a graphical interface, a simulation engine, a route planning module, a task assignment module, a collision manager, and a test suite. The final version implements four route planning algorithms: A*, Dijkstra, BFS, and Greedy Best-First Search. It also includes two assignment criteria: nearest taxi and priority user.

The problem is formulated as a graph search problem, where each traversable grid cell corresponds to a node and each valid movement to an adjacent cell represents an edge. Based on this representation, the system evaluates routes between taxis and users while considering distance, user priority, and occupancy restrictions.

The system was validated through a test suite covering pathfinding, multi-agent assignment, collision handling, route replanning, random scenario generation, and configurable numbers of taxis and users. The final test result was 28 successful tests and 0 errors.

\textbf{Keywords:} multi-agent robotics, motion planning, graph search, A*, Dijkstra, BFS, Greedy Best-First, optimization, computational simulation, task assignment.

\section{Introducción}
\justifying

La planeación de movimiento es un problema fundamental en robótica, inteligencia artificial y sistemas autónomos. Su objetivo consiste en determinar una secuencia de movimientos que permita a un agente desplazarse desde una posición inicial hasta una posición objetivo, evitando obstáculos y cumpliendo restricciones del entorno.

Cuando el problema involucra más de un agente, la complejidad aumenta significativamente. Además de calcular rutas individuales, es necesario coordinar el movimiento colectivo, evitar colisiones, asignar tareas de manera eficiente y resolver conflictos cuando dos o más agentes intentan ocupar la misma celda o cruzar posiciones simultáneamente.

Este tipo de problema aparece en aplicaciones como robots móviles en bodegas, vehículos autónomos, drones cooperativos, sistemas de reparto, videojuegos, simuladores urbanos y plataformas de transporte inteligente. Por esta razón, el análisis de algoritmos de búsqueda y estrategias de coordinación resulta especialmente relevante dentro de una asignatura de métodos y modelos computacionales.

En este proyecto, el espacio de trabajo se modela como una grilla de $20 \times 20$. Cada celda puede representar una calle, un edificio, un taxi, una ruta calculada o un usuario. Los taxis se desplazan únicamente en cuatro direcciones cardinales: arriba, abajo, izquierda y derecha. No se permite atravesar obstáculos ni ocupar simultáneamente una celda con otro taxi.

La implementación permite seleccionar el algoritmo de ruta y el criterio de asignación desde la interfaz gráfica. Esta separación es importante: el algoritmo de ruta define cómo se calcula el camino entre un taxi y un usuario, mientras que el criterio de asignación define qué taxi atiende a qué usuario.

\section{Formulación del Problema}
\justifying

Se considera un espacio de trabajo discreto definido por una grilla rectangular:

\begin{equation}
W = \{(r,c) \mid 0 \leq r < 20,\; 0 \leq c < 20\}
\end{equation}

donde $r$ representa la fila y $c$ representa la columna de una celda. Dentro de este espacio existen obstáculos, taxis y usuarios.

Sea:

\begin{itemize}
    \item $A = \{a_1,a_2,\dots,a_n\}$ el conjunto de taxis o agentes.
    \item $U = \{u_1,u_2,\dots,u_m\}$ el conjunto de usuarios o tareas.
    \item $O \subset W$ el conjunto de obstáculos.
    \item $p_j \in \{1,2,3\}$ la prioridad del usuario $u_j$.
    \item $x_i(k)$ la posición del taxi $a_i$ en el instante discreto $k$.
    \item $q_j$ la posición del usuario $u_j$.
\end{itemize}

Cada taxi puede desplazarse a una celda adyacente válida. El conjunto de movimientos permitidos está dado por:

\begin{equation}
(r,c) \rightarrow (r+1,c)
\end{equation}

\begin{equation}
(r,c) \rightarrow (r-1,c)
\end{equation}

\begin{equation}
(r,c) \rightarrow (r,c+1)
\end{equation}

\begin{equation}
(r,c) \rightarrow (r,c-1)
\end{equation}

siempre que la nueva celda esté dentro de la grilla y no pertenezca al conjunto de obstáculos.

El objetivo general del sistema consiste en completar todas las tareas minimizando el costo de desplazamiento y evitando conflictos entre taxis. Una formulación general del costo puede expresarse como:

\begin{equation}
J = \sum_{(i,j)\in \mathcal{M}} d(a_i,u_j)
\end{equation}

donde $\mathcal{M}$ representa el conjunto de asignaciones taxi-usuario y $d(a_i,u_j)$ es la longitud de la ruta calculada entre el taxi $a_i$ y el usuario $u_j$.

% =========================
% MODELADO COMO GRAFO
% =========================
\section{Modelado Matemático como Grafo}
\justifying

El entorno se representa mediante un grafo no dirigido:

\begin{equation}
G = (V,E)
\end{equation}

donde $V$ es el conjunto de celdas transitables y $E$ el conjunto de conexiones entre celdas adyacentes.

El conjunto de nodos se define como:

\begin{equation}
V = W \setminus O
\end{equation}

y el conjunto de aristas se define como:

\begin{equation}
E = \{((r,c),(r',c')) \mid |r-r'| + |c-c'| = 1\}
\end{equation}

siempre que ambas celdas pertenezcan a $V$.

Esta representación permite transformar el problema de navegación en un problema de búsqueda de caminos sobre grafos. Cada taxi busca una ruta desde su posición actual hasta la posición del usuario asignado.

La distancia Manhattan utilizada como heurística se define como:

\begin{equation}
h(n) = |r_n-r_g| + |c_n-c_g|
\end{equation}

donde $(r_n,c_n)$ es la posición del nodo actual y $(r_g,c_g)$ es la posición objetivo.

% =========================
% RESTRICCIONES DE COLISIÓN
% =========================
\section{Restricciones de Movimiento y Colisión}
\justifying

El sistema implementa reglas para evitar conflictos entre taxis. La primera restricción impide que dos taxis ocupen la misma celda en el mismo instante:

\begin{equation}
x_i(k) \neq x_l(k), \quad \forall i \neq l
\end{equation}

La segunda restricción evita colisiones por intercambio de posición. Esto ocurre cuando dos taxis intentan intercambiar sus celdas simultáneamente:

\begin{equation}
\neg \left[x_i(k+1)=x_l(k) \land x_l(k+1)=x_i(k)\right]
\end{equation}

Adicionalmente, cuando existe un conflicto local, el sistema aplica una regla de derecho de paso. Esta regla favorece al taxi que atiende al usuario de mayor prioridad. En caso de empate, se favorece al taxi con menor distancia restante hacia su objetivo. Si el empate persiste, se utiliza el identificador del taxi como criterio determinista de desempate.

\section{Algoritmos de Ruta Implementados}
\justifying

Los algoritmos de ruta permiten calcular el camino desde un taxi hasta un usuario. En todos los casos, el problema se resuelve sobre el grafo asociado a la grilla.

\subsection{A*}

A* combina el costo acumulado desde el nodo inicial con una estimación heurística hacia el objetivo. Su función de evaluación se define como:

\begin{equation}
f(n)=g(n)+h(n)
\end{equation}

donde $g(n)$ es el costo acumulado y $h(n)$ es la distancia Manhattan estimada hasta el objetivo.

A* resulta adecuado para este proyecto porque dirige la búsqueda hacia el objetivo sin ignorar el costo real acumulado.

\subsection{Dijkstra}

Dijkstra calcula caminos mínimos considerando el costo acumulado desde el origen. En esta implementación, cada movimiento tiene costo unitario, por lo que Dijkstra puede encontrar rutas mínimas en número de pasos.

A diferencia de A*, Dijkstra no utiliza heurística. Por esta razón, puede explorar más nodos antes de llegar al objetivo.

\subsection{Breadth-First Search}

BFS explora el grafo por niveles. En grafos no ponderados, como la grilla utilizada en este proyecto, BFS encuentra rutas mínimas en número de pasos.

Su implementación utiliza una cola FIFO para procesar los nodos en el orden en que son descubiertos.

\subsection{Greedy Best-First Search}

Greedy Best-First Search utiliza únicamente la heurística para decidir qué nodo explorar primero. En este proyecto se usa distancia Manhattan como función heurística.

Este método puede encontrar rutas rápidamente, pero no garantiza la ruta más corta, ya que no considera el costo acumulado del recorrido.

% CRITERIOS DE ASIGNACIÓN
% =========================
\section{Criterios de Asignación de Tareas}
\justifying

Además del cálculo de rutas, el sistema debe decidir qué taxi atiende a cada usuario. Para ello se implementaron dos criterios de asignación.

Es importante diferenciar entre algoritmo de ruta y criterio de asignación. El algoritmo de ruta calcula el camino entre un taxi y un usuario sobre la grilla; por ejemplo, A*, Dijkstra, BFS o Greedy Best-First. En cambio, el criterio de asignación decide qué taxi atiende a qué usuario usando la información entregada por el algoritmo de ruta. Por esta razón, un mismo escenario puede generar decisiones distintas si se cambia el criterio de asignación, aunque el algoritmo de ruta sea el mismo.

\subsection{Taxi más cercano}

Este criterio evalúa las rutas posibles entre taxis disponibles y usuarios pendientes. Para cada par taxi-usuario se calcula una ruta y se obtiene su longitud:

\begin{equation}
d_{ij} = |\pi_{ij}|
\end{equation}

donde $\pi_{ij}$ es la ruta calculada entre el taxi $a_i$ y el usuario $u_j$.

La asignación se realiza seleccionando la menor distancia:

\begin{equation}
(i^*,j^*) = \arg\min_{i,j} d_{ij}
\end{equation}

Este criterio prioriza la reducción del tiempo estimado de llegada.

\subsection{Usuario prioritario}

En este criterio se atienden primero los usuarios con mayor prioridad. Las prioridades se codifican de la siguiente manera:

\begin{table}[H]
\centering
\caption{Codificación de prioridades de usuarios}
\begin{tabular}{ccc}
\toprule
\textbf{Color} & \textbf{Prioridad} & \textbf{Significado} \\
\midrule
Azul & 1 & Normal \\
Morado & 2 & Importante \\
Rojo & 3 & Urgente \\
\bottomrule
\end{tabular}
\end{table}

Primero se selecciona el usuario con mayor prioridad:

\begin{equation}
j^* = \arg\max_j p_j
\end{equation}

Luego se asigna el taxi con menor distancia hacia dicho usuario:

\begin{equation}
i^* = \arg\min_i d_{ij^*}
\end{equation}

Este criterio permite simular situaciones donde no basta con atender al usuario más cercano, sino que se debe considerar la urgencia de la solicitud.

\section{Resultados y Discusión}
\justifying

El sistema desarrollado permitió verificar el funcionamiento de la planeación de movimiento multi-agente en un entorno discreto. Los taxis fueron capaces de calcular rutas hacia los usuarios, evitar obstáculos, respetar reglas de colisión y completar tareas bajo distintos escenarios.

Desde el punto de vista algorítmico, A*, Dijkstra y BFS permiten encontrar rutas válidas sobre la grilla. En entornos no ponderados, BFS y Dijkstra pueden producir rutas equivalentes en longitud, aunque su estrategia de exploración difiere. A* incorpora una heurística que dirige la búsqueda hacia el objetivo, lo cual resulta conveniente para navegación en grillas.

Greedy Best-First Search también encontró rutas válidas en los escenarios probados, pero su comportamiento depende fuertemente de la heurística. Debido a que no considera el costo acumulado, puede producir rutas menos convenientes en presencia de obstáculos.

En cuanto a la asignación, el criterio de taxi más cercano prioriza la minimización de la distancia inmediata, mientras que el criterio de usuario prioritario permite atender primero solicitudes urgentes. Esta diferencia permite analizar cómo una misma configuración de taxis y usuarios puede generar decisiones distintas dependiendo del criterio seleccionado.

% =========================
% LIMITACIONES
% =========================
\section{Limitaciones}
\justifying

Aunque el sistema cumple con los objetivos planteados, existen algunas limitaciones:

\begin{itemize}
    \item Los obstáculos no cambian de posición durante la ejecución de la simulación.
    \item El movimiento se limita a cuatro direcciones cardinales.
    \item No se modela aceleración, velocidad continua ni dinámica física real de los vehículos.
    \item La comparación de algoritmos se realizó principalmente de manera funcional y cualitativa.
    \item La asignación implementada utiliza criterios heurísticos locales, por lo que no resuelve una optimización global exacta para todos los taxis y usuarios de forma simultánea.
\end{itemize}

\section{Conclusiones}
\justifying

El proyecto permitió desarrollar una solución funcional para el problema de planeación de movimiento multi-agente en un entorno discreto. Mediante la representación del espacio como un grafo, fue posible aplicar algoritmos de búsqueda clásicos para calcular rutas entre taxis y usuarios.

La separación entre algoritmo de ruta y criterio de asignación resultó fundamental para organizar correctamente el problema. Los algoritmos A*, Dijkstra, BFS y Greedy Best-First determinan cómo se calcula el camino, mientras que los criterios de taxi más cercano y usuario prioritario determinan cómo se asignan las tareas.

La implementación de reglas de colisión permitió evitar conflictos por ocupación simultánea de celdas y por intercambio de posiciones. Además, la replaneación dinámica ayudó a resolver bloqueos persistentes causados por otros taxis detenidos en la ruta.

La suite de pruebas permitió verificar el comportamiento principal del sistema y confirmó que los módulos implementados funcionan de forma integrada. El resultado de 28 pruebas aprobadas y 0 errores proporciona evidencia de que el sistema cumple con los requerimientos funcionales principales del examen.

En general, el desarrollo de SmartRide Planner permitió integrar conceptos vistos en la asignatura, especialmente búsqueda sobre grafos, asignación de tareas y coordinación multi-agente. La simulación no pretende representar toda la complejidad de un sistema real de transporte, pero sí permite observar de manera clara cómo diferentes algoritmos y criterios de decisión afectan el comportamiento de los agentes en un entorno discretizado.
